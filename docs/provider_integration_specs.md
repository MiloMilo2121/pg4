# Provider integration specs (doc-grounded, from workflow wjku9q22k)

## Serper
- roles: SEARCH_WEB
- base_url: https://google.serper.dev
- auth: API key in custom header `X-API-KEY: <key>`. In this engine store it as env var SERPER_API_KEY and inject it into the X-API-KEY request header. No Bearer prefix. Content-Type: application/json required on POST.
- pricing: Credit-based top-up (pay-as-you-go), no monthly subscription. Web search consumes 1 credit per query (multi-page/num>10 and heavier types consume more credits). Effective rate scales by volume: ~$1.00 per 1,000 queries at entry tier down to ~$0.30 per 1,000 queries at high volume. Currency: USD.
- free_tier: 2,500 free credits on signup, no credit card required. Credits valid ~6 months.
- rate_limits: No firm published RPS figure in official docs. Practical concurrency is generous (advertised 1-2s latency per query; service positions itself for high-throughput agent/SEO use). Treat as effectively limited by credit balance; implement client-side concurrency caps and retry/backoff on 429/5xx. (UNVERIFIED exact numeric limit.)
- sdk_or_http: Raw HTTP (POST JSON). No official Node/TS SDK published by Serper — call via fetch/axios. (Third-party wrappers exist in LangChain/CrewAI but are not Serper-official; prefer raw HTTP.)
- confidence: 0.82
- docs: https://serper.dev/ | https://serper.dev/playground | https://serper.dev/api-keys | https://docs.crewai.com/en/tools/search-research/serperdevtool | https://apitracker.io/a/serper-dev
- gotchas: - It is `X-API-KEY` (not Authorization Bearer); 401/403 = missing/wrong key, billing error = out of credits. - Base host is `google.serper.dev` (note the `google.` subdomain), not `serper.dev` or `api.serper.dev`. - All calls are POST with JSON body even though they're 'searches' (no query-string GET). - `num` caps at 100; >10 may cost extra credits; use `page` for pagination. - `gl`/`hl`/`location` strongly affect results — set them explicitly for IT/EU lead work (gl=it, hl=it). - Enrichment blocks (knowledgeGraph, answerBox, peopleAlsoAsk, relatedSearches, sitelinks) are conditional — always null-check before access. - Each response includes a `credits` field; meter it to track spend. - No official SDK: type the response yourself; field presence varies by query.

### endpoints
- **search** POST /search — Google web SERP — primary SEARCH_WEB role. Returns organic results plus enrichments.
   req: JSON body: { "q": "acme corp ceo" (required), "gl": "it" (country code, optional), "hl": "it" (UI language, optional), "location": "Milan, Italy" (optional, granular geo), "num": 10 (results 10-100, optional), "page": 1 (optional), "tbs": "qdr:m" (optional time filter), "autocorrect": true (optional) }
   resp: JSON: { searchParameters:{q,gl,hl,type,engine}, knowledgeGraph?:{title,type,website,description,attributes}, answerBox?:{title,answer,snippet}, organic:[{title,link,snippet,position,sitelinks?,date?}], peopleAlsoAsk?:[{question,snippet,title,link}], relatedSearches?:[{query}], credits:Number }
- **scholar** POST /scholar — Google Scholar academic search.
   req: JSON body: { "q": "deep learning lead scoring" (required), "gl":string?, "hl":string?, "num":number?, "page":number? }
   resp: JSON: { searchParameters:{q,type:"scholar",engine}, organic:[{title,link,snippet,publicationInfo,year?,citedBy?,pdfUrl?,id?}], credits:Number }
- **news** POST /news — Google News results.
   req: { q (required), gl?, hl?, num?, page?, tbs? }
   resp: { searchParameters, news:[{title,link,snippet,date,source,imageUrl,position}], credits }
- **places** POST /places — Google Maps/local places — useful for enriching company location/contact.
   req: { q (required), gl?, hl?, location?, num? }
   resp: { searchParameters, places:[{position,title,address,latitude,longitude,rating?,ratingCount?,category?,phoneNumber?,website?,cid}], credits }
- **images** POST /images — Google Images results.
   req: { q (required), gl?, hl?, num? }
   resp: { searchParameters, images:[{title,imageUrl,imageWidth,imageHeight,thumbnailUrl,source,link,position}], credits }
- **shopping** POST /shopping — Google Shopping results.
   req: { q (required), gl?, hl?, num? }
   resp: { searchParameters, shopping:[{title,source,link,price,imageUrl,rating?,ratingCount?,position}], credits }

## Tavily
- roles: SEARCH_WEB
- base_url: https://api.tavily.com
- auth: HTTP header `Authorization: Bearer tvly-YOUR_API_KEY`. In this engine the key is read from env var TAVILY_API_KEY (the @tavily/core SDK auto-reads TAVILY_API_KEY, or pass tavily({ apiKey: process.env.TAVILY_API_KEY })).
- pricing: Credit-based. Pay-as-you-go $0.008/credit USD; monthly plans $0.005–$0.0075/credit. Cost per /search: basic/fast/ultra-fast = 1 credit; advanced = 2 credits; auto_parameters enabled = 2 credits (reducible by explicitly setting search_depth). So a basic search ≈ $0.008, advanced ≈ $0.016 at PAYG.
- free_tier: 1,000 free API credits/month, no credit card required (Researcher tier). Keyless mode also exists (no apiKey) with shared rate-limited access to search+extract only.
- rate_limits: Default RPM: Development key = 100 RPM, Production key = 1,000 RPM. On exceed: HTTP 429 with `retry-after` header (implement retry respecting it). (Other endpoints differ: Crawl 100 RPM both, Research 20 RPM, Usage 10 req/10min.)
- sdk_or_http: Official SDK: npm `@tavily/core` (TypeScript/JS, repo tavily-ai/tavily-js). Raw HTTP also fully supported (POST JSON).
- confidence: 0.9
- docs: https://docs.tavily.com/documentation/api-reference/endpoint/search | https://docs.tavily.com/documentation/api-credits | https://docs.tavily.com/documentation/rate-limits | https://docs.tavily.com/documentation/api-reference/introduction | https://docs.tavily.com/sdk/javascript/get-started | https://www.npmjs.com/package/@tavily/core | https://github.com/tavily-ai/tavily-js
- gotchas: 1) API key prefix is `tvly-`; header must be `Authorization: Bearer tvly-...` (Bearer scheme, not raw x-api-key). 2) advanced search_depth doubles credit cost (2 vs 1) — set search_depth explicitly to avoid auto_parameters silently charging 2 credits. 3) chunks_per_source only applies when search_depth='advanced'. 4) include_raw_content/include_images/include_answer increase payload and latency but do NOT add credits for /search (depth is the only cost driver). 5) max_results caps at 20. 6) include_domains max 300 / exclude_domains max 150. 7) safe_search is Enterprise-only. 8) Use include_usage:true or read usage.credits in the response to track spend. 9) /search is POST only (no GET).

### endpoints
- **Tavily Search** POST /search — AI web search optimized for LLM/agent consumption: returns ranked results with extracted content, optional LLM-generated answer, optional raw page content and images. Primary SEARCH_WEB call.
   req: JSON body. Required: query (string). Common optional: search_depth ('basic'|'advanced'|'fast'|'ultra-fast', default 'basic'), topic ('general'|'news'|'finance', default 'general'), max_results (int 0-20, default 5), chunks_per_source (int 1-3, advanced only, default 3), include_answer (bool|'basic'|'advanced', default false), include_raw_content (bool|'markdown'|'text', default false), include_images (bool), include_image_descriptions (bool), include_favicon (bool), include_domains (string[], max 300), exclude_domains (string[], max 150), country (string), time_range ('day'|'week'|'month'|'year'|'d'|'w'|'m'|'y'), start_date/end_date ('YYYY-MM-DD'), auto_parameters (bool, default false), exact_match (bool), include_usage (bool), safe_search (bool, Enterprise only). Example: {"query":"strutture metalliche fornitori Veneto","search_depth":"advanced","max_results":10,"include_answer":"advanced","country":"italy"}
   resp: JSON: { query: string, answer?: string, images?: [{url, description?}], results: [{ title: string, url: string, content: string, score: number, raw_content?: string, favicon?: string }], auto_parameters?: object, response_time: number, usage?: { credits: number }, request_id: string }

## Exa
- roles: SEARCH_WEB, CONTENTS
- base_url: https://api.exa.ai
- auth: API key in the `x-api-key` request header (alternatively `Authorization: Bearer <key>`). In this Node/TS engine store the key in env var EXA_API_KEY (the official exa-js SDK reads EXA_API_KEY automatically; `new Exa()` with no arg picks it up, or pass it explicitly `new Exa(process.env.EXA_API_KEY)`).
- pricing: USD, usage-based (also returned per-call in response.costDollars). Search: $7 per 1,000 requests base (covers up to 10 results) + $1 per 1,000 for each result beyond 10. Per-page contents: $1 per 1,000 pages per content type (text / highlights / summary each billed separately, ~ $0.001/page each). AI summaries: $1 per 1,000 pages across endpoints. Deep search: $12/1k (deep) to $15/1k (deep-reasoning). Monitors: $15/1k. Legacy neural-search tier pricing also seen as $0.005/request for 1-25 results, $0.025 for 26-100, $1.00 for 100+. Agent/answer effort tiers: $0.012 (minimal) to $1.00 (x-high) per request.
- free_tier: Free: up to 20,000 requests per month at no cost. Startup grants: up to $1,000 in free credits available.
- rate_limits: Default tier: /search = 10 QPS, /contents = 100 QPS. Higher limits (up to ~2000 QPS) available; enterprise plans offer custom QPS. Build retry/backoff on 429.
- sdk_or_http: Official SDK: npm package `exa-js` (github.com/exa-labs/exa-js). Raw HTTP also fully supported (POST JSON). For a lead engine the SDK is recommended: typed methods search(), searchAndContents(), getContents(), answer().
- confidence: 0.88
- docs: https://exa.ai/docs/reference/search | https://exa.ai/docs/reference/get-contents | https://exa.ai/docs/reference/rate-limits | https://exa.ai/pricing?tab=api | https://exa.ai/docs/sdks/typescript-sdk-specification | https://github.com/exa-labs/exa-js
- gotchas: 1) docs.exa.ai now 307-redirects to exa.ai/docs (and api host stays api.exa.ai). 2) The legacy type values 'neural' and 'keyword' are deprecated in favor of type:'auto'|'fast'|'instant'|'deep*'; 'auto' picks neural vs keyword automatically — if you need pure keyword behavior, verify the current type enum rather than assuming 'keyword' still works. 3) costDollars is returned per response — use it for live cost accounting instead of estimating. 4) Each content type (text, highlights, summary) is billed independently, so requesting all three triples per-page cost — request only what the lead engine needs. 5) Prefer searchAndContents() (single call) over search() + getContents() to avoid double round-trips, but note inline contents adds to search cost. 6) maxAgeHours=-1 forces a fresh livecrawl (slower, may hit livecrawlTimeout). 7) findSimilar() is deprecated. 8) results from /search may omit text/highlights/summary unless a contents object is passed. 9) numResults>100 jumps into a much higher pricing tier.

### endpoints
- **search** POST /search — SEARCH_WEB — neural/keyword/auto web search returning ranked results; can return page contents inline via the contents object (use searchAndContents() in SDK).
   req: JSON body. Required: query (string, min 1 char). Key optional fields: type (enum: auto[default], fast, instant, deep-lite, deep, deep-reasoning), numResults (1-100, default 10), category (company|research paper|news|personal site|financial report|people), includeDomains (string[], max 1200), excludeDomains (string[], max 1200), startPublishedDate / endPublishedDate (ISO8601), startCrawlDate / endCrawlDate (ISO8601), userLocation (2-letter ISO country), moderation (bool). To get page text inline pass contents object: { text: bool | {maxCharacters, includeHtmlTags, verbosity}, highlights: bool | {query, maxCharacters}, summary: {query?, schema?}, livecrawl/maxAgeHours (-1..720), subpages (0-100), livecrawlTimeout (ms, default 10000) }. NOTE: classic 'neural' vs 'keyword' is now folded into type='auto'/'fast'; older API exposed type:'neural'|'keyword'.
   resp: { requestId: string, results: [{ id: string, url: string, title: string, score?: number, publishedDate?: string, author: string|null, image?: string, favicon?: string, text?: string, highlights?: string[], highlightScores?: number[], summary?: string, subpages?: [...], entities?: [...], extras?: {links:[]} }], costDollars: { total: number, search: { neural: number } } }
- **getContents** POST /contents — CONTENTS — fetch full text / highlights / summary / live-crawled page content for a set of URLs or Exa result IDs.
   req: JSON body. Required (one of): urls (string[], 1-100, max 2048 chars each) OR ids (string[], 1-100, Exa result IDs). Optional: text (bool | {maxCharacters 1-10000, includeHtmlTags, verbosity: compact|standard|full, includeSections, excludeSections}), highlights (bool | {query, maxCharacters 1-10000}), summary ({query, schema}), extras ({links, imageLinks, richImageLinks, richLinks, codeBlocks — each 0-1000}), maxAgeHours (-1..720; -1 forces livecrawl), subpages (0-100), subpageTarget (string|string[]), livecrawlTimeout (ms, max 90000, default 10000).
   resp: { requestId: string, results: [{ id, url, title, publishedDate, author, image, favicon, text, highlights, highlightScores, summary, subpages, entities, extras }], statuses: [{ id, status, source, error }], costDollars: { total: number } }

## Perplexity
- roles: SEARCH_WEB, LLM_ANSWER
- base_url: https://api.perplexity.ai
- auth: HTTP Bearer. Header: `Authorization: Bearer <key>`. In this engine the key lives in env var PERPLEXITY_API_KEY (the name used in all official examples). OpenAI SDK: new OpenAI({ apiKey: process.env.PERPLEXITY_API_KEY, baseURL: "https://api.perplexity.ai" }).
- pricing: Pay-as-you-go, USD, no subscription required. Token pricing per 1M tokens: sonar $1 in / $1 out; sonar-pro $3 in / $15 out; sonar-reasoning-pro $2 in / $8 out; sonar-deep-research $2 in / $8 out (+ $2/1M citation tokens, $3/1M reasoning tokens). PLUS per-request search fees per 1,000 requests, scaled by web_search_options.search_context_size: sonar & sonar-reasoning-pro = $5 (low)/$8 (med)/$12 (high); sonar-pro = $6/$10/$14 (with Pro Search $14/$18/$22). sonar-deep-research bills search at ~$5 per 1,000 queries. Net: budget per grounded answer = token cost + the request/search fee, not tokens alone.
- free_tier: No standing free API tier / no monthly API credits documented for pay-as-you-go API usage (consumer Perplexity Pro subscription is separate and does not grant these API endpoints). Access is usage-based; you must add credits. Some Perplexity Pro plans have historically included a small recurring API credit as a perk, but it is not part of the documented API pricing — do not rely on it.
- rate_limits: Tiered by cumulative API spend (Tier 0–5); tiers are permanent (no downgrade) and unlock higher RPM. Default for sonar online models is 50 requests/min for all users. Leaky-bucket algorithm allows bursts with continuous token refill. Custom limits beyond Tier 5 via a rate-limit-increase request form. Check exact per-tier RPM in the API Platform console.
- sdk_or_http: Two supported paths. (1) Raw HTTP / OpenAI-compatible: use the official `openai` npm package pointed at baseURL https://api.perplexity.ai and call client.chat.completions.create — this is what Perplexity's own TS quickstart shows. (2) Official native TS SDK: `@perplexity-ai/perplexity_ai` (npm). For a lead engine, OpenAI-compatible (`openai` pkg or raw fetch to /chat/completions) is the lowest-friction, most-documented route. Python equivalent is `perplexityai`.
- confidence: 0.85
- docs: https://docs.perplexity.ai/api-reference/chat-completions-post | https://docs.perplexity.ai/api-reference/chat-completions | https://docs.perplexity.ai/getting-started/quickstart | https://docs.perplexity.ai/guides/chat-completions-sdk | https://docs.perplexity.ai/getting-started/pricing | https://docs.perplexity.ai/guides/usage-tiers
- gotchas: 1) Endpoint ambiguity: docs now show a native route `POST /v1/sonar`, but the stable OpenAI-compatible path used by the `openai` SDK and raw HTTP is `POST /chat/completions` with baseURL https://api.perplexity.ai — use /chat/completions for OpenAI-compat code. 2) Cost is NOT token-only: every request also incurs a per-request search fee driven by search_context_size — set web_search_options.search_context_size:'low' to cut cost when high recall isn't needed. 3) Citations vs search_results: `citations` is a flat URL list; `search_results` carries title/url/snippet/date — prefer search_results for lead enrichment. 4) sonar-reasoning-pro emits <think> reasoning tokens in content (and bills reasoning); strip before storing. 5) sonar-deep-research is slow (multi-minute) and can be expensive — not for per-lead realtime loops. 6) search_domain_filter both whitelists and (with '-' prefix) blacklists domains — powerful for restricting to authoritative sources. 7) For retrieval-only, /search is cheaper than a full chat completion. 8) response_format JSON-schema is supported — use it to get structured lead fields directly. 9) WebSearch is US-only here; confirm any per-tier RPM numbers in the live console as they change with spend.

### endpoints
- **Chat Completions (search + grounded answer)** POST /chat/completions — Single call that performs live web search AND returns an LLM-synthesized answer with citations — covers both SEARCH_WEB and LLM_ANSWER roles. Use sonar/sonar-pro for grounded answers; sonar-reasoning-pro for chain-of-thought; sonar-deep-research for multi-step research reports. The OpenAI-compatible path; works with the `openai` npm client (client.chat.completions.create) and with raw fetch.
   req: JSON. Required: model (string: 'sonar' | 'sonar-pro' | 'sonar-reasoning-pro' | 'sonar-deep-research'), messages (array of {role:'system'|'user'|'assistant', content:string}). Search/answer-relevant optional fields: search_mode ('web'|'academic'|'sec'), search_domain_filter (string[], allow/deny domains, prefix '-' to exclude), search_recency_filter ('hour'|'day'|'week'|'month'|'year'), search_after_date_filter / search_before_date_filter (date strings), web_search_options ({ search_context_size: 'low'|'medium'|'high', user_location }), return_related_questions (bool), return_images (bool), reasoning_effort ('minimal'|'low'|'medium'|'high'), disable_search (bool), enable_search_classifier (bool), response_format (JSON schema for structured output), max_tokens (int, up to 128000), temperature (0-2), top_p, stream (bool, SSE).
   resp: JSON: { id, object:'chat.completion', created (unix int), model, choices:[{ index, finish_reason, message:{ role:'assistant', content:string } }], citations: string[] (source URLs), search_results:[{ title, url, snippet, date }], images?: [{ url, ... }], related_questions?: string[], usage:{ prompt_tokens, completion_tokens, total_tokens, search_queries_count, cost? } }. With stream:true you get SSE chunks with choices[].delta.content.
- **Search API** POST /search — Raw web search WITHOUT LLM synthesis — returns ranked search results only. Use this when the engine needs pure SEARCH_WEB (retrieval) and will do its own downstream reasoning, cheaper/lower-latency than a full chat completion for retrieval-only needs.
   req: JSON: { query (string or string[]), max_results (int), search_domain_filter, search_recency_filter, country, ... }.
   resp: JSON: { results: [{ title, url, snippet, date, last_updated }], ... }.

## OpenAI
- roles: LLM_REASON, EMBEDDINGS
- base_url: https://api.openai.com/v1
- auth: Bearer token in the `Authorization: Bearer <key>` header (Content-Type: application/json). Key is read from env var OPENAI_API_KEY (already wired in this engine: pg4/src/config/env.ts validates OPENAI_API_KEY, OPENAI_MODEL, OPENAI_ENABLED; pg1/.env.example and pg3/.env.example also use OPENAI_API_KEY). Optional org/project scoping via OpenAI-Organization / OpenAI-Project headers.
- pricing: Per 1M tokens, USD (verify on live pricing page — values shift). LLM: gpt-4o-mini ≈ $0.15 in / $0.60 out; gpt-4.1-mini ≈ $0.40 in / $1.60 out. Embeddings: text-embedding-3-small ≈ $0.02; text-embedding-3-large ≈ $0.13 per 1M tokens (NOTE: OpenAI's own pages show a $0.065 vs $0.13 discrepancy for 3-large — confirm before relying on it); text-embedding-ada-002 ≈ $0.10. Batch API ~50% discount. Note: 10% uplift on regional/data-residency processing for models released on/after 2026-03-05.
- free_tier: No ongoing free tier. New accounts historically got limited trial credits that expire; production usage is pay-as-you-go (prepaid credits / billing). Treat as paid-only for this engine.
- rate_limits: Per-account, per-model RPM (requests/min) and TPM (tokens/min) by usage tier (Free→Tier 5; limits rise with cumulative spend). Embeddings hard input limits: 8192 tokens per input, max 2048 array entries, max 300,000 tokens summed across all inputs in one request. 429 on limit — back off and retry (the openai SDK auto-retries with exponential backoff). Check headers x-ratelimit-remaining-requests / x-ratelimit-remaining-tokens.
- sdk_or_http: Official npm SDK: `openai` (import OpenAI from "openai"; const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY })). Raw HTTP also fully supported against the same /v1 endpoints. SDK is the recommended path for Node/TS (typed, retries, streaming helpers).
- confidence: 0.83
- docs: https://developers.openai.com/api/docs/api-reference/responses/create | https://developers.openai.com/api/docs/guides/migrate-to-responses | https://developers.openai.com/api/docs/guides/responses-vs-chat-completions | https://developers.openai.com/api/docs/api-reference/chat/object | https://developers.openai.com/api/docs/api-reference/embeddings/create | https://developers.openai.com/api/docs/guides/embeddings | https://developers.openai.com/api/docs/pricing | https://developers.openai.com/api/docs/models/text-embedding-3-small | https://developers.openai.com/api/docs/models/text-embedding-3-large
- gotchas: 1) Two text endpoints: prefer /v1/responses (current) over /v1/chat/completions; structured-output param differs — Responses uses text.format, Chat uses response_format. 2) Responses usage uses input_tokens/output_tokens; Chat uses prompt_tokens/completion_tokens — don't mix when computing cost. 3) Reasoning/o-series & gpt-5.x models may ignore temperature and use reasoning.effort instead; reasoning tokens are billed as output. 4) Embeddings: set `dimensions` to shrink 3-large/3-small vectors (saves storage) but it must match across all stored vectors. 5) platform.openai.com blocks plain GET fetchers (403) — use the SDK/curl with auth, not scrapers. 6) Engine guards: OPENAI_ENABLED defaults false in pg4 — must be set true plus a valid OPENAI_API_KEY. 7) Pricing discrepancy on 3-large across OpenAI's own docs — verify before cost models. 8) Never put OPENAI_API_KEY in client-side code.

### endpoints
- **Responses API (create) — PREFERRED for LLM_REASON** POST /v1/responses — Primary current text-generation/reasoning endpoint. Use for lead scoring/classification/extraction prompts. Supports structured JSON output via text.format json_schema (strict).
   req: { model: string (e.g. "gpt-4o-mini" / "gpt-4.1-mini" / "gpt-5.5"), input: string | array (the user content), instructions?: string (system/developer prompt), max_output_tokens?: number, temperature?: number, text?: { format?: { type: "json_schema", name: string, strict: true, schema: {...JSON-Schema} } }, tools?: [...], reasoning?: { effort: "low"|"medium"|"high" }, stream?: boolean }
   resp: { id: string, object: "response", model: string, output: [{ type:"message", role:"assistant", content:[{ type:"output_text", text: string }] }], output_text: string (SDK convenience aggregate), usage: { input_tokens: number, output_tokens: number, total_tokens: number } }
- **Chat Completions (create) — alternative for LLM_REASON** POST /v1/chat/completions — Stable legacy-compatible chat endpoint. Use if code already speaks the messages[] format. Structured output via response_format json_schema.
   req: { model: string, messages: [{ role: "system"|"user"|"assistant", content: string }], max_tokens?: number, temperature?: number, response_format?: { type: "json_schema", json_schema: { name: string, strict: true, schema: {...} } }, reasoning_effort?: "low"|"medium"|"high", stream?: boolean }
   resp: { id: string, object: "chat.completion", created: number, model: string, choices: [{ index: number, message: { role: "assistant", content: string, refusal: null }, finish_reason: "stop" }], usage: { prompt_tokens: number, completion_tokens: number, total_tokens: number } }
- **Embeddings (create) — EMBEDDINGS role** POST /v1/embeddings — Generate vector embeddings for lead text (ICP similarity, dedup, clustering). Batch by passing input as an array of strings.
   req: { model: "text-embedding-3-small" | "text-embedding-3-large" | "text-embedding-ada-002", input: string | string[] | number[] | number[][], dimensions?: number (3-series only, reduce vector size), encoding_format?: "float"|"base64", user?: string }
   resp: { object: "list", data: [{ object: "embedding", index: number, embedding: number[] (1536 dims for 3-small/ada-002, 3072 for 3-large unless dimensions set) }], model: string, usage: { prompt_tokens: number, total_tokens: number } }

## Anthropic Claude
- roles: LLM_REASON
- base_url: https://api.anthropic.com
- auth: API key in the `x-api-key` request header (NOT `Authorization: Bearer`). Plus required `anthropic-version: 2023-06-01` header. In a Node/TS engine, the key is read from the `ANTHROPIC_API_KEY` env var — the official SDK (`new Anthropic()`) picks it up automatically; never hardcode it client-side.
- pricing: Claude Opus 4.8 (`claude-opus-4-8`, recommended judge model): $5.00 per 1M input tokens / $25.00 per 1M output tokens (USD). Cheaper judge options: Claude Sonnet 4.6 ($3/$15), Claude Haiku 4.5 ($1/$5). Prompt caching: cache writes ~1.25x input (5m TTL) or ~2x (1h TTL), cache reads ~0.1x input — cache the stable rubric/ICP prefix to cut judge cost up to ~90%. Message Batches API: 50% off all token usage. Highest-capability tier (rarely needed for judging): Claude Fable 5 $10/$50.
- free_tier: No free tier. Usage is prepaid/billed credits via the Claude Console (console/platform.claude.com). New accounts may receive limited promotional credit but there is no standing free quota for the API.
- rate_limits: Per-organization tier-based limits: requests-per-minute (RPM), input-tokens-per-minute (ITPM), output-tokens-per-minute (OTPM), and tokens-per-day on some tiers. Exact numbers scale with usage tier (1-4) and are listed at platform.claude.com/docs/en/api/rate-limits. 429 responses carry a `retry-after` header and `x-ratelimit-*` headers; the official SDK auto-retries 429/5xx with exponential backoff (default max_retries=2).
